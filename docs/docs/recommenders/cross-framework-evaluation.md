# Cross-Framework Evaluation

WarpRec supports evaluating recommendation lists generated by **external frameworks** through the `ProxyRecommender`. This allows researchers and practitioners to leverage WarpRec's comprehensive evaluation suite -- 40+ GPU-accelerated metrics, statistical significance testing, and sampled evaluation -- on recommendations produced outside of WarpRec.

!!! info "API Reference"

    For class signatures and parameters, see the [Unpersonalized API Reference](../api-reference/recommenders/unpersonalized.md).

## Use Case

When you have precomputed recommendation lists from another library (e.g., Surprise, LensKit, RecBole, or a custom production system), you can use the `ProxyRecommender` to evaluate them within WarpRec's standardized evaluation pipeline without retraining.

This is particularly useful for:

- **Benchmarking** external models against WarpRec's built-in algorithms using identical evaluation protocols.
- **Reproducing** results from published papers by feeding their recommendation files into WarpRec's evaluation engine.
- **Comparing** models across different frameworks in a consistent and fair manner.

## How It Works

The `ProxyRecommender` reads a precomputed recommendation file and presents it to WarpRec's evaluation system as if it were generated by an internal model. This means you get access to all of WarpRec's metrics, cutoffs, and reporting features.

The recommendation file is a tabular file with one row per recommended (user, item) pair and its score. With a header, the columns must be named `user_id`, `item_id` and `rating` (the score), and the ids must be integers; without a header, the first three columns are read in that order. The separator is the one configured below:

```
user_id	item_id	rating
1	42	0.95
1	17	0.87
2	42	0.62
2	5	0.54
...
```

The ids are the original ones of the dataset, not WarpRec's indices; rows naming a user or item the dataset does not know, or carrying a nonfinite score, are dropped.

By default, `missing_policy: zero` preserves the upstream contract: every pair
the file does not list scores **0**. A missing user therefore has a full row of
zeros, a short list is completed with unlisted items, and those zeros rank above
listed negative scores. Use positive scores when replaying a complete top-k
ordering under this convention.

For faithful import of partial lists, explicitly choose
`missing_policy: unavailable`. Every unlisted pair then scores `-inf`:

- a user missing from the file is still evaluated, with an empty list: accuracy is zero when that user has relevant test items, while list averages such as ARP and APLT are undefined;
- a list shorter than the cutoff stays short; unlisted pairs earn no hits or exposure;
- finite negative and explicit zero scores remain valid and retain their order. No positive score shift is needed.

See [Partial recommendation lists](../evaluation/partial-rankings.md) for denominators and empty-list handling. In sampled prediction, catalogue-padding IDs are also unavailable, rather than aliases for the final real item.

## Configuration

```yaml
models:
  ProxyRecommender:
    recommendation_file: /path/to/recommendations.tsv
    separator: "\t"
    header: True
    missing_policy: unavailable  # opt in to exact listed-pair semantics
```

The `recommendation_file` parameter points to the file containing the precomputed recommendation lists. WarpRec will load these recommendations and pass them through the configured evaluation pipeline, producing the same output artifacts (evaluation reports, statistical tests, etc.) as for any built-in model.
